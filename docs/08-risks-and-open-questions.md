# 08. 리스크 & 결정할 것

## 1. 리스크

### 제품
| 리스크 | 영향 | 대응 |
|---|---|---|
| **기존 커뮤니티의 네트워크 효과** | 굳이 옮기지 않음 | "대체"가 아니라 "재밌는 추가 공간"으로 시작. 학교 단위로 밀도 집중 |
| **게임 요소가 귀찮음** | 정보만 원하는 사용자 이탈 | 리스트 모드 상시 제공, H4로 측정 ([12](12-mvp-and-validation.md)) |
| **초기에 섬이 텅 빔** | 첫인상이 쓸쓸함 | 비동기 주민 ([11](11-core-loop.md)), 사전예약자로 오픈 첫날 랜드마크 진척 |
| **학과 동물 때문에 익명이 깨짐** | 작은 학과 학생 신원 노출 | 익명 글은 공통 아바타가 기본 ([13](13-community-policy.md)) |
| **경쟁 과열 & 비방** | 분위기 악화 | 비하 금지, 제재 시 점수 차감, 협력 이벤트 병행 |
| **학과 동물에 대한 불만** | "우리 학과 동물 싫어요" | 사전 투표, 무늬·소품으로 개성 표현 |

### 기술 & 아트
| 리스크 | 영향 | 대응 |
|---|---|---|
| **3D 성능** | 저사양 폰에서 느림, 배터리 소모 | 성능 등급 4단계, 리스트 모드 폴백 ([06](06-tech-architecture.md)) |
| **3D 아트 비용·시간** | 퀄리티가 핵심인데 1인 개발로 부족 | 공통 건물 재사용, 랜드마크만 학교별 제작, 외주 검토 |
| **특정 게임과 비슷해 보임** | 저작권, 상표 분쟁 | 캐릭터, 아트, UI, 이름 모두 오리지널. 특정 게임의 캐릭터·에셋·명칭 사용 금지 |
| **학교별 랜드마크 제작** | 학교 수만큼 모델 필요 | 공통 베이스 + 장식 교체, 오픈 대기 기간에 제작 |
| **점수 어뷰징** | 대항전 신뢰도 하락 | [03 문서](03-activity-score.md)의 방지책 |

### 운영 & 법
| 리스크 | 영향 | 대응 |
|---|---|---|
| **익명 커뮤니티 운영 부담** | 법적 책임, 1인 운영 과부하 | 자동 블라인드, 섬지기, 처리 기준 문서화 ([13](13-community-policy.md)) |
| **개인정보** | 유출 시 큰 타격 | 최소 수집, 메일 해시 보관 검토, 출시 전 법률 검토 |
| **학교 상징물 권리** | 로고·교표·공식 캐릭터 무단 사용 시 분쟁 | 쓰지 않음. 건물 외관을 참고한 오리지널 모델만 |
| **학과 개편** | 동물 매핑 변경 | `colleges` 테이블로 관리, 기존 사용자에게 선택권 |

## 3. 결정 대기
| 질문 | 추천안 | 문서 |
|---|---|---|
| 익명 글에 학과 동물을 보여줄까? | **기본은 공통 아바타, 원하면 공개** | [13](13-community-policy.md) |
| 처음 화면을 섬으로 할까, 게시판으로 할까? | 섬 (저사양 기기는 리스트) → 파일럿 데이터로 재검토 | [12](12-mvp-and-validation.md) |
| MVP에 실시간 멀티플레이를 넣을까? | **넣지 않음**. 비동기 주민으로 대신 | [11](11-core-loop.md) |
| 3D 아트는 누가 만드나? | 캐릭터·랜드마크는 외주, 소품은 직접 | [07](07-roadmap.md) |
| 공식 마스코트 '스쿠아' 제휴 제안? | 파일럿 반응을 본 뒤 제안 | [10](10-pilot-sungkyul.md) |
| 서비스 이름 | 섬 컨셉에 맞게 재검토 (예: 캠퍼스섬) | [01](01-overview.md) |
| 성결대 재학생 수 (N) | 대학알리미로 확인 | [12](12-mvp-and-validation.md) |
| 활성도 가중치 | 파일럿 데이터로 보정 | [03](03-activity-score.md) |
