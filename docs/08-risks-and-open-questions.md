# 08. 리스크 & 결정할 것

## 1. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| **기존 커뮤니티의 네트워크 효과** | 사람들이 굳이 옮기지 않음 | "대체"가 아니라 "재밌는 추가 공간"으로 시작. 학교 단위 밀도 집중 |
| **게임 요소가 귀찮음** | 정보만 원하는 유저가 이탈 | 리스트 모드 상시 제공, 섬은 선택 |
| **특정 게임과 비슷해 보이는 디자인** | 저작권, 상표 분쟁 | 캐릭터, 아트, UI, 이름 모두 오리지널로 제작. 특정 게임의 캐릭터나 에셋, 명칭 사용 금지 |
| **경쟁 과열 & 비방** | 커뮤니티 분위기 악화 | 비방 점수 차감, 교류전 등 협력 이벤트 병행 |
| **익명 커뮤니티 모더레이션** | 법적 책임, 운영 부담 | 신고 자동 블라인드, AI 필터, 학교별 섬지기 제도 |
| **개인정보 (학교 이메일)** | 유출 시 큰 타격 | 이메일은 인증 후 해시 저장 검토, 최소 수집 |
| **점수 어뷰징** | 대항전 신뢰도 하락 | [03 문서](03-activity-score.md)의 방지책 + 이상 학교 점수 검토 |
| **아트 비용** | 귀여움이 핵심인데 비용이 큼 | MVP는 소수 에셋으로 시작, 동물은 학교 색 틴트로 재사용 |
| **학교별 랜드마크 제작 비용** | 학교 수만큼 일러스트 필요 | 공통 베이스 + 장식 교체 방식, 오픈 요청 대기 기간에 제작 |
| **학교 상징물 권리** | 로고, 교표, 공식 캐릭터 무단 사용 시 분쟁 | 로고와 교표는 사용하지 않음. 건물 외관을 참고한 오리지널 일러스트만 사용, 필요 시 학교 허가 |
| **학부별 동물 고정에 대한 불만** | "우리 학부 동물 싫어요" | 사전 투표로 결정, 무늬와 소품으로 개성 표현 보장 |
| **학부 개편** | 학부 통폐합 시 동물 매핑 변경 | `colleges` 테이블로 학교별 매핑 관리, 기존 유저는 선택권 부여 |
| **1인 개발 운영 부담** | 모더레이션, CS 과부하 | 파일럿 학교 수 제한, 운영 자동화 우선 |
