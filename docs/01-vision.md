# 01. 비전과 원칙

## 1. 목적

> **전국 대학생이 지금 쓰는 대학 커뮤니티 대신 쓰는 플랫폼을 만든다.**

그러려면 두 가지가 동시에 필요하다.

1. **대신 쓸 수 있을 만큼 실용적이어야 한다.** 시간표, 강의평, 게시판이 지금 쓰는 앱만큼은 돼야 한다.
2. **옮겨 올 이유가 있어야 한다.** 참여, 경쟁, 보상으로 쓰는 재미와 소속감이 생겨야 한다.

## 2. 문제

| 지금 대학 커뮤니티 | 결과 |
|---|---|
| 게시판 목록 중심이라 **볼거리, 재미가 없음** | 필요할 때만 들어갔다 나감 |
| 좋은 글, 강의평을 써도 **돌아오는 것이 없음** | 소수만 쓰고 대다수는 읽기만 함 |
| 학교 안의 활동이 **눈에 보이지 않음** | 우리 학교 커뮤니티가 살아 있는지 느낄 수 없음 |
| 학교끼리 **연결도, 비교도 없음** | 소속감과 경쟁심을 쓸 수 없음 |

## 3. 해결: 캠퍼스 산

학교마다 **캠퍼스 부지 모양의 3D 산**이 있다. 모두 산 아래 베이스캠프에서 시작하고, 위쪽은 안개에 덮여 있다. 학생들이 **서로에게 도움이 되는 활동**을 할수록 기여가 쌓이고, 학교 전체의 기여로 안개가 걷히며, 정상에는 우리 학교 대표 건물이 있다.

```
                 🏛️ 정상: 학교 대표 건물 (시즌의 목표)
               ☁️☁️☁️ 안개 (학교 전체 기여로 걷힘) ☁️☁️☁️
              ── 전망대 ── 다른 학교 산, 전국 게시판
            ──── 중턱 ──── 학과 라운지, 계절 공간
          ────── 산길 ────── 장터, 스터디, 동아리
        ════ 베이스캠프 ════ 시간표 · 강의평 · 학식 · 게시판 (처음부터 전부 열림)
```

## 4. 설계 원칙

| # | 원칙 | 의미 |
|---|---|---|
| 1 | **산은 이유가 아니라 결과다** | 사람들은 필요한 걸 하러 온다. 그 활동이 쌓여서 산을 오르게 된다 |
| 2 | **기본 기능은 절대 잠그지 않는다** | 시간표, 강의평, 게시판 읽기·쓰기는 첫날부터 전부 열림. 잠기면 원래 쓰던 앱으로 돌아간다 |
| 3 | **기여 = 다른 학생에게 도움이 된 행동** | 강의평, 답변 채택, 정보 제보가 가장 큰 기여. 그래서 등반 경쟁이 곧 커뮤니티 활성화가 된다 |
| 4 | **혜택은 편해지거나 예뻐지는 것만** | 다른 사람보다 위에 서는 힘(노출 우선, 투표 가중치)은 주지 않는다 |
| 5 | **3D는 선택이다** | 3D 산은 홈 화면 위쪽의 분위기와 진행도. 아래 카드와 리스트 모드만으로도 모든 기능을 쓸 수 있다 |
| 6 | **익명은 지킨다** | 경쟁과 캐릭터가 익명을 깨면 안 된다 ([07 문서](07-community-policy.md)) |

## 5. 타깃 사용자

| 페르소나 | 지금 | 이 서비스에서 |
|---|---|---|
| 🐣 **새내기 지민 (20)** | 학교에 아는 사람 없음, 시간표 짜기 막막함 | 시간표·강의평으로 시작 → 질문 게시판에서 선배 답변 → 학과 라운지에서 소속감 |
| 📚 **3학년 도윤 (23)** | 강의평, 정보글 위주로 읽기만 함 | 강의평·답변을 쓰면 기여가 쌓이고 "가이드" 등급과 배지를 받음 |
| 🔥 **과대 서연 (22)** | 학과 행사 홍보, 학과 단톡 관리 | 학과 등반대를 이끌어 주간 1위, 학교 대항전에서 우리 학교 정상 정복 |
| 🍱 **통학생 민호 (21)** | 학식, 셔틀, 빈 강의실 정보가 늘 아쉬움 | "지금 캠퍼스"로 실시간 정보 확인, 제보하면 기여 |

## 7. 서비스 이름 (가칭)

산 컨셉으로 바뀌어서 이름을 다시 정한다. 문서에서는 당분간 **"캠퍼스산"**을 가칭으로 쓴다.

| 후보 | 느낌 |
|---|---|
| **캠퍼스산** | 직관적. "성결산", "OO산"으로 학교별 이름이 자연스러움 |
| 등교 | "학교에 간다"와 "올라간다"의 이중 의미 |
| 올라 | 짧고 밝음, 등반 컨셉 |
| 유니빌 | 이전 가칭. 산 컨셉과는 어긋남 |
