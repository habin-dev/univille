# 09. MVP & 검증 계획

> MVP는 "다 있는 첫 버전"이 아니라 **핵심 가설을 확인하는 가장 작은 버전**이다. 다만 목표가 "지금 앱을 대신하기"이므로 **1층 실용 기능은 MVP에 반드시 들어간다.**

## 1. 검증할 가설

| # | 가설 | 맞다면 | 틀리면 |
|---|---|---|---|
| H1 | 시간표·강의평이 **매일 열 이유**를 만든다 | 시간표 등록률, D7이 높다 | 1층 기능을 더 편하게 다듬기 |
| H2 | 벽돌과 건물 완공이 **도움이 되는 행동을 늘린다** | 강의평·답변·제보가 꾸준히 늘어난다 | 기여 점수표·혜택 재설계 |
| H3 | 학과 건축팀이 **참여 인원을 넓힌다** | 기여한 학생 비율이 오른다 | 경쟁 대신 협력 목표 중심으로 |
| H4 | 3D 캠퍼스가 **정보만 원하는 사람을 쫓아내지 않는다** | 리스트 모드 사용자도 잘 남는다 | 홈을 카드 중심으로, 캠퍼스는 축소 |

## 2. 개발 전 (Step 0, 3~4주)

| 할 일 | 통과 기준 (초안) |
|---|---|
| **강의 데이터 확보 방법 확정** (공개 자료 / 학생 입력) | 성결대 이번 학기 과목 80% 이상을 목록으로 만들 수 있다 |
| 성결대 학생 15~20명 인터뷰 (캠퍼스 짓기 컨셉 + 기능 구성) | 절반 이상 "시간표·강의평이 되면 써보겠다" |
| 랜딩 페이지 + 사전예약 + 학과 동물 카드 | 재학생의 3% 이상 사전예약 |
| 사전예약자 강의평 씨앗 모으기 | 오픈 전 강의평 200개 |

### 인터뷰 질문
1. 지금 쓰는 학교 커뮤니티 앱은 하루에 몇 번, 무엇 때문에 여나요?
2. 그 앱에서 가장 불편한 것 하나는?
3. 강의평이나 답변을 쓰면 무언가를 받는다면, 무엇이면 좋겠나요?
4. 강의평을 쓰면 도서관이 지어지는 식으로 우리 캠퍼스를 같이 짓는다는 아이디어, 어떤가요? 귀찮을 것 같나요?
5. 학과끼리 경쟁하면 참여하고 싶나요, 부담스럽나요?
6. "지금 캠퍼스"에 어떤 정보가 있으면 하루에 여러 번 열겠어요?

## 3. MVP 범위 (성결대 파일럿)

### ✅ 만든다
| 층 | 범위 |
|---|---|
| 기본 | `@sungkyul.ac.kr` 메일 인증, 학과 선택 → 학과 동물 |
| 1층 | **시간표**, **강의평**, 학식(사진·평점), 학사일정 D-day |
| 2층 | 게시판 (자유, 정보, 고민, 학과별), **질문 & 답변**, **지금 캠퍼스 제보** |
| 3층 | 장터 |
| 4층 | 벽돌, 건물 완공 (모든 역할 건물 + 랜드마크), 개인 등급 2단계(견습생·목수), 학과 건축팀·학과 하우스, 오늘의 목표 |
| 5층 | 학과 동물 캐릭터 기본형, 건축 장비 2종 |
| 캠퍼스 | 성결 캠퍼스 1개 (부지·건물 데이터 기반), 임시 천막촌, 공사 단계 연출, 홈 화면 위쪽 3D 캠퍼스 + 아래 카드, 전체 화면에서 캐릭터 조작, 비동기 주민 |
| 운영 | 신고·차단·자동 블라인드, 관리자 페이지, 이벤트 로깅 |
| 플랫폼 | 모바일 웹 (PWA) |

### ❌ 미룬다 (v1 이후)
공지 요약, 스터디·팀플 매칭, 같이 밥·택시, 분실물, 동아리 거리, 학과 라운지 꾸미기, 건물 안 공간 꾸미기·증축, 건축가·총괄 건축가 등급, 코인 상점, 실시간 멀티플레이, 다른 학교·학교 대항, 앱스토어 출시

## 4. 파일럿 성공 기준 (오픈 후 8주)

재학생 수 = **N** (대학알리미로 확인 예정)

| 지표 | 목표 | 가설 |
|---|---|---|
| 가입자 | N의 **15%** | |
| 가입자 중 시간표 등록 | **60%** | H1 |
| D7 리텐션 | **35%** | H1 |
| 강의평 수 | **500개** (과목 커버리지 30%) | H2 |
| 기여한 적 있는 학생 | 가입자의 **40%** | H3 |
| 리스트 모드 사용자 D7 | 캠퍼스 사용자 D7의 70% 이상 | H4 |
| 첫 건물 완공 | 오픈 후 **2주 안** | 완공 기준 수치 보정 |
| 신고 처리 | 24시간 이내 | 운영 |

### 방향 전환 기준
- 시간표 등록률이 **30% 미만**이면: 1층이 경쟁력이 없다는 뜻. 캠퍼스·벽돌보다 1층을 먼저 고친다.
- D7이 **20% 미만**이면: 기능 추가를 멈추고 이탈자 10명 인터뷰.
- 기여가 소수에 몰리면 (상위 5%가 기여의 70% 이상): 참여 인원 조건과 오늘의 목표를 조정.

## 5. 측정 이벤트

| 이벤트 | 용도 |
|---|---|
| `signup_completed` (학과) | 가입 |
| `timetable_saved` (과목 수) | H1 |
| `home_opened` (모드: 캠퍼스/리스트, 성능 등급) | H1, H4 |
| `review_created`, `answer_accepted`, `report_helpful` | H2 |
| `bricks_earned` (행동, 개수, 건물) | 기여 분포 |
| `building_completed` | 완공 속도 |
| `daily_goal_completed` | 오늘의 목표 난이도 |
| `crew_rank_viewed` | H3 |
| `post_created`, `comment_created`, `market_deal_done` | 활성도 |
| `report_created`, `report_resolved` | 운영 |

> 이벤트에는 학교, 학과, 익명 ID만 담고 글 내용·이메일은 담지 않는다.
